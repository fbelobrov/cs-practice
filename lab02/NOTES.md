Рабочая папка — это твоя локальная директория на компьютере, где лежат все файлы проекта. Здесь ты редактируешь код, добавляешь новые файлы, удаляешь старые. По сути, это твоё "боевое пространство".
Индекс (staging area) — промежуточная зона между рабочей папкой и историей проекта. Когда ты делаешь `git add`, файлы переходят в индекс. Это как подготовка к фотографии: ты выбираешь, какие изменения "сфотографировать", а какие оставить в стороне.
Коммит — снимок твоего проекта в конкретный момент времени. Когда ты делаешь `git commit`, все файлы из индекса "замораживаются" в истории с сообщением, описывающим, что изменилось. Это вроде сохранения игры: потом всегда можешь вернуться к этому моменту.
Git — это система контроля версий, которая позволяет отслеживать изменения в коде и работать с несколькими версиями проекта одновременно. Она работает локально, на твоём компьютере.
GitHub — это облачная платформа для хостинга и управления Git-репозиториями. Она добавляет социальные функции, такие как пулл-реквесты, обсуждения и совместная работа с другими разработчиками. GitHub использует Git как основу, но расширяет его возможности онлайн.
«Использованные команды»:
git status — показывает текущее состояние рабочей папки. Какие файлы изменены, какие не отслеживаются, что уже в индексе. Быстрый обзор, что происходит.
git diff — сравнивает рабочую папку с индексом. Показывает конкретные изменения в файлах: какие строки добавлены, какие удалены, что изменено. Видишь ровно то, что ты писал, но ещё не добавил через git add.
git diff --staged — сравнивает индекс с последним коммитом. Показывает, какие изменения уже готовы к коммиту (те, что в индексе). Это превью того, что будет в следующем снимке проекта.
«Ветки»:
Ветка — это отдельная линия развития проекта. По умолчанию у тебя есть main (или master), но ты можешь создать свою ветку, чтобы работать над фичей или багфиксом, не трогая основной код. Каждая ветка — это просто указатель на определённый коммит.
Когда ты делаешь новый коммит на ветке, указатель этой ветки сдвигается вперёд на новый коммит. Коммиты образуют цепочку: каждый новый коммит "знает" о предыдущем. Если ты работаешь на ветке feature, а потом на main создаётся новый коммит, ветки начинают расходиться — у них разные истории.
Слияние (merge) — это объединение двух веток. Ты берёшь изменения из одной ветки (например, feature) и вносишь их в другую (например, main). Git старается автоматически совместить изменения. Если изменения не конфликтуют — слияние проходит гладко. Если два человека менял один и тот же код — возникает конфликт, который нужно решить вручную.
