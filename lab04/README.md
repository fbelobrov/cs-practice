# Практика 04: устойчивый разбор метеожурнала

Формат одной записи: `город;температура;дата`.
Решение использует стандартную библиотеку Python 3.9 или новее.

## Как запустить

Из корня репозитория:

```text
python lab04/main.py
```

Введите журнал. В Windows завершите ввод сочетанием Ctrl+Z и Enter;
в Linux/macOS — Ctrl+D.

Вход:

```text
Азов;24.5;2026-07-01
мусор
Азов;25.5;2026-07-02
Таганрог;30;2026-07-01
```

Выход:

```text
3
1
30.0
```

Азов: `(24.5 + 25.5) / 2 = 25.0`. Таганрог: `30 / 1 = 30.0`.
Корректных записей три; строка «мусор» содержит ошибку.

## Основные идеи решения

### 1. Разделение на модули

`stats.py` содержит четыре функции без чтения с клавиатуры и печати:

- `parse_record(line)` возвращает словарь с ключами `city`, `temperature`, `date`.
- `read_valid(lines)` возвращает список корректных записей.
- `average_by_city(records)` возвращает словарь средних температур по городам.
- `warmest_city(records)` возвращает название самого тёплого города.

`main.py` отвечает за ввод и вывод. Условие `if __name__ == "__main__"`
запускает программу только при непосредственном запуске файла.
Импорт модуля не читает ввод и не печатает отчёт.

### 2. Проверка в одном месте

`parse_record` делит строку по `;`, проверяет число полей, удаляет пробелы
по краям каждого поля, проверяет непустые город и дату, преобразует температуру.
Запятая заменяется точкой: `-3,5` превращается в `-3.5`.
Преобразование `float` может возбудить `ValueError`; функция перехватывает
его и возбуждает новый `ValueError` с понятным сообщением.
Конструкция `raise ... from error` сохраняет исходную причину ошибки.

Дата хранится строкой. Проверка календарной корректности не добавлена:
в условии требуется только непустое поле даты.

### 3. Обнаружить ошибку и решить, что с ней делать — разные задачи

`parse_record` сообщает об ошибке через исключение. `read_valid` вызывает её
внутри `try`, перехватывает только `ValueError` и переходит к следующей строке.
Поэтому один испорченный элемент не прерывает обработку всего журнала.
Пустые и состоящие из пробелов строки `read_valid` пропускает заранее.

`read_valid` по условию возвращает только список, а не пару «список, счётчик».
Поэтому число ошибок вычисляется в `main.py`:

```python
nonempty_count = sum(1 for line in lines if line.strip())
skipped_count = nonempty_count - len(records)
```

У каждой непустой строки ровно один исход: корректная запись или ошибка.
Повторно разбирать строки для подсчёта ошибок не нужно.

### 4. Средние и выбор города

Для каждого города накапливаются сумма температур и число наблюдений.
Среднее равно сумме, делённой на количество; `round(value, 1)` округляет
результат до десятых. Отрицательные температуры обрабатываются так же.

`warmest_city` использует средние из `average_by_city`. Ключ
`(-averages[city], city)` позволяет выбрать через `min` сначала наибольшую
температуру, а при равенстве — наименьшее название по алфавиту.
Сравниваются средние, уже округлённые до десятых.

Для вывода применяется `:.1f`: оно гарантирует один знак после точки,
в том числе `30.0`, и не добавляет подписи, которых нет в образце.

## Неоднозначности скриншотов

- Полные ожидаемые словари в таблице тестов обрезаны. Использованы ключи
  `city`, `temperature`, `date`; видимые фрагменты согласуются с этими именами.
- Поддержка десятичной запятой следует из видимого скрытого примера `-3,5`.
- Для пустого списка `average_by_city` возвращает `{}`, `warmest_city` — `""`.
  Если корректных записей нет, третья строка отчёта — `0.0`.
  Эти значения для `warmest_city` и отчёта прямо не заданы на скриншотах.
- Порядок сравнения до или после округления не уточнён. Здесь выбор города
  согласован с результатом `average_by_city`: сравниваются округлённые средние.

## Проверка

Из корня репозитория:

```text
python -m unittest discover -s lab04 -v
```

Проверяются образец задания, ошибки формата, пустые поля и строки,
пробелы, десятичная запятая, усреднение, округление, отрицательные температуры,
алфавитное разрешение равенства и пустой журнал.
