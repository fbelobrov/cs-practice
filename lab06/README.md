# Практика 06. Файловая система в Python

Условие: http://46.149.66.58/assignments/9.
Обязательный файл — `lab06/solution.py`, Python 3.9+.
Функции получают готовые данные, возвращают результат и не читают реальные файлы.

## 1. Подсчёт расширений

`count_by_extension(paths)` сначала выделяет имя файла после последнего `/`:

```python
filename = path.rsplit("/", 1)[-1]
```

Затем берёт часть после последней точки, если она есть, и переводит её
в нижний регистр. В словаре увеличивается счётчик такого расширения.

| Путь | Расширение | Почему |
| --- | --- | --- |
| `docs/report.PDF` | `pdf` | Нижний регистр |
| `archive.tar.gz` | `gz` | Только после последней точки |
| `folder.name/Makefile` | `""` | В имени самого файла нет точки |
| `.gitignore` | `gitignore` | Буквальное правило задания: после последней точки |
| `file.` | `""` | После точки нет символов |

Для пустого списка возвращается `{}`. Повторяющиеся пути считаются повторно:
функция считает элементы переданного списка, а не уникальные имена.

Здесь не используется `Path.suffix`: у скрытого файла `.gitignore` он дал бы
пустую строку, что отличается от буквального правила этой практики.

## 2. Самый вложенный путь

`deepest_path(paths)` считает символы `/` в каждой строке. Используется
`min` с ключом `(-path.count("/"), path)`:

- отрицательное число разделителей выбирает наибольшую вложенность;
- сама строка пути выбирает первый по алфавиту при равной вложенности;
- `default=""` задаёт результат для пустого списка.

Например, между `x/y/z.txt` и `a/b/c.txt` выбирается `a/b/c.txt`,
независимо от порядка элементов во входе. Пути не нормализуются: согласно
условию считаются именно символы `/`, а не реальные каталоги на компьютере.

## 3. Размер в удобных единицах

`human_size(n_bytes)` выбирает единицу из `Б`, `КБ`, `МБ`, `ГБ`, `ТБ`.
Пока размер не меньше 1024 и доступна следующая единица, делит размер на 1024.

| Байты | Результат |
| ---: | --- |
| 0 | `0 Б` |
| 900 | `900 Б` |
| 1024 | `1.0 КБ` |
| 1536 | `1.5 КБ` |
| 5242880 | `5.0 МБ` |
| 3221225472 | `3.0 ГБ` |
| 1099511627776 | `1.0 ТБ` |

Формат `:.1f` обеспечивает один знак после точки, включая `.0`.
Используется стандартное округление Python. Выбор единицы делается до округления.
Вход — целое неотрицательное число байтов. Последняя предусмотренная единица — ТБ;
даже для больших размеров функция не вводит отсутствующие в задании единицы.

## Использование

Из корня репозитория:

```python
from lab06.solution import count_by_extension, deepest_path, human_size

paths = ["docs/report.PDF", "notes.txt", "docs/img/logo.png", "Makefile"]
assert count_by_extension(paths) == {"pdf": 1, "txt": 1, "png": 1, "": 1}
assert deepest_path(paths) == "docs/img/logo.png"
assert human_size(1536) == "1.5 КБ"
```

При запуске самого `solution.py` вывода нет: проверяющий сервис импортирует
модуль и вызывает функции со своими аргументами.
