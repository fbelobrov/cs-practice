# Практика 05. Построчная обработка журнала

Обязательные файлы: `logstats.py`, `main.py`, исходные `events.log` и
`events-small.log`, сгенерированный `report.txt`. Используется Python 3.9+,
сторонние библиотеки не нужны.

## Запуск

Из папки `lab05`:

```text
python main.py
```

Затем ввести имя файла и нажать Enter:

```text
events.log
```

Программа напечатает строго три числа:

```text
29
7
2
```

Это число обработанных непустых строк (включая испорченные), число корректных
событий уровня `ERROR` и число испорченных строк. Пустые строки не учитываются.

Для `events-small.log` результат — `4`, `2`, `0` на отдельных строках.
Можно запускать и из корня репозитория командой `python lab05/main.py`.
Путь берётся из ввода: сначала относительно текущей рабочей папки,
а если такой относительный путь не найден — относительно папки скрипта.
Абсолютный путь используется как есть.

Отчёт всегда записывается рядом с `main.py`, в UTF-8 с переводами строк LF.
Каждый запуск перезаписывает его. В репозитории сохранён отчёт для полного
`events.log`; после проверки короткого журнала полный был обработан повторно.

## Как устроено решение

### Разбор строки — `parse_event`

```python
parts = line.strip().split(maxsplit=2)
```

`strip` убирает внешние пробелы и перевод строки. `maxsplit=2` разрешает только
два разделения: сообщение со всеми его внутренними пробелами остаётся третьей
частью. Возвращается словарь с ключами `time`, `level`, `message`.

Допустимы только `DEBUG`, `INFO`, `WARNING`, `ERROR`. Недостаток полей,
отсутствующее сообщение или неизвестный уровень приводят к `ValueError`.
Время остаётся строкой: отдельная календарная проверка в задании не требуется.

### Подсчёт — `count_levels`

Функция проходит по входу обычным `for`, пропускает пустые строки и вызывает
`parse_event`. Для корректного события увеличивается счётчик его уровня.
Если перехвачен `ValueError`, увеличивается `BROKEN`, затем обработка продолжается.
В словарь входят только встретившиеся категории; пустой вход даёт `{}`.

### Частые ошибки — `top_errors`

Учитываются только корректные события `ERROR`. Словарь хранит количество
повторений каждого сообщения. Сортировка использует ключ
`(-количество, сообщение)`: сначала большая частота, затем алфавит.
Результат — список из не более `n` пар-списков `[сообщение, количество]`.
Если ошибок нет или `n <= 0`, результат — `[]`.

### Текст — `format_report`

Функция получает готовые счётчики, сортирует названия уровней по алфавиту,
добавляет раздел «Частые ошибки:» и завершающий перевод строки.
Пары ошибок выводятся в переданном порядке: `top_errors` уже упорядочил их.
В строках ошибок используются дефис перед сообщением и длинное тире перед числом.

### Ввод и запись — `main.py`

Модуль `logstats.py` не читает с клавиатуры, не открывает файлы и ничего не печатает.
`main.py` читает путь из первой строки ввода, дважды открывает журнал и передаёт
открытый файловый объект функциям обработки. Для отчёта берутся три частые ошибки,
как в образце задания. Защита `if __name__ == "__main__"` исключает запуск при импорте.

## Что объяснить на защите

- `for line in log` обрабатывает файл последовательно. Ни `read()`, ни
  `readlines()`, ни превращения всего журнала в список в решении нет.
- Открытый файл является итерируемым объектом: функции одинаково работают со
  списком, генератором и файловым объектом. Поэтому аннотация `Iterable[str]`
  точнее, чем `list[str]`; имена и порядок аргументов соответствуют заданию.
- После первого прохода файл находится в конце. Его повторное открытие
  позволяет второму проходу начать с начала, не сохраняя журнал в памяти.
- `with` закрывает файл при выходе из блока, в том числе при исключении.
- `encoding="utf-8"` явно задаёт кодировку и сохраняет русские сообщения
  независимо от системной кодировки компьютера.
- Построчное чтение не означает, что вся программа использует постоянную память:
  для частот нужен словарь уникальных сообщений ERROR. Память зависит от числа
  разных сообщений, а не от числа всех строк. Сортировка также хранит эти сообщения.

## Исходные данные и результат

Журналы скопированы из предоставленных файлов без правок. В `.gitattributes`
для `*.log` отключено преобразование переводов строк Git, чтобы сохранить байты.
SHA-256 исходников и копий совпадают:

```text
events.log
bb19da8e53b5d4318e4ea7d10b007c61be175d321e9a8be86cd08a4417d30de2

events-small.log
9ff87015530dce0139b624cdde02d221e21466687870c24f8bfd568f9ebcc5ba
```

Полный журнал: `BROKEN: 2`, `DEBUG: 4`, `ERROR: 7`, `INFO: 11`, `WARNING: 5`.
Частые ошибки: «Не удалось открыть файл data.csv» — 4,
«Превышено время ожидания» — 2, «Нет доступа к каталогу /var/log» — 1.

## Проверки и сдача

Из корня репозитория:

```text
python -m unittest discover -s lab05 -v
```

15 тестов проверяют разбор, ошибки, пробелы, уровни, порядок при равных частотах,
пустой вход, точный формат отчёта, оба исходных журнала, одноразовый итератор,
генератор из 100 000 строк, отсутствие ввода/вывода при импорте и запуск программы
с произвольным именем файла. Тест запуска создаёт временную копию программы,
поэтому не перезаписывает сдаваемый `report.txt`.

Работа разделена на четыре коммита: разбор и подсчёт уровней; частые ошибки
и форматирование; файловый ввод/вывод; исходные журналы, отчёт, тесты и пояснения.
Для сдачи указать https://github.com/fbelobrov/cs-practice и ветку `main`,
каталог практики — `lab05`.
